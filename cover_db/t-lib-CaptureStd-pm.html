1package CaptureStd;
2#
3# capture { ... } for the test suite: runs the block with STDOUT and STDERR
4# on temporary files and returns (stdout, stderr, what the block returned).
5# It stands in for Capture::Tiny's capture(), which the tests used before 0.18
6# and which was then their only reason to need Capture::Tiny; the calling
7# convention is that one's, from the Capture::Tiny 0.50 documentation: the
8# block runs in list context, an exception from it propagates once the
9# handles are restored, and $? is left as the block left it.
10#
11# It deliberately works differently from SimpleFlow::_capture, which it is
12# used to test. That redirects descriptors 1 and 2 with POSIX::dup2; this
13# reopens the STDOUT and STDERR globs, and relies on perl reopening a handle
14# whose descriptor is at or below $^F (2) onto that same descriptor -- the
15# fd <= PL_maxsysfd case in doio.c's open code, checked here on perl 5.10.1
16# and 5.44.0, both of which keep STDOUT on fd 1 even with fd 0 closed.
17# A bug in the module's capture therefore cannot be hidden by the same bug in
18# the harness measuring it.
19#
20# Only what the tests need is here: no tee, no merge, no layers beyond
21# undoing MSWin32's CR LF (every capture compared is ASCII), no tied or closed
22# standard handles.
23#
